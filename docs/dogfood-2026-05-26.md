# Dogfood Findings — Coffee Video, 2026-05-26

End-to-end test: a 299-character Chinese script about coffee's global supply
chain, paired with 6 real YouTube stock-footage clips (yt-dlp), 60s TTS
voiceover, rendered through the full pipeline (index → plan → render).
Output: 11 scenes, 70.7s, ~9.8MB at 1280×720.

Result: **the pipeline runs end-to-end, but quality is not ready for
publish**. Below is the punch list, ranked by severity.

---

## 🔴 P0 — must fix before any real dogfood

### 1. Silent stock footage → no transcript → not indexed
**Where it bit us**: all 6 YouTube clips were B-roll without narration. The
first `vocut index` returned `clips_added: 0` — Whisper transcribed silence
into nothing, and `store_file_and_clips` skipped them entirely.

**Workaround landed in-session**: filename fallback in
`index.py::transcribe_file`. When `segments` is empty AND
`VOCUT_FILENAME_FALLBACK!=0`, one synthetic segment is created with the
file stem as the description text (e.g. `pour-on-grounds` → "pour on
grounds"). This gets clips into the DB but downstream quality suffers
(see #2).

**Proper fix**: visual content captioning. Run a vision LLM (BLIP-2 / CLIP /
GPT-4o-vision) on a few sampled frames per clip; concatenate captions as the
clip's description text before embedding. Filename fallback can stay as the
"no API key" path.

### 2. One clip eats the whole video
**Symptom**: `picking-coffee.mp4` appeared in **7 of 11 scenes** (4 footage +
3 hybrid). Other clips were used 1× or 0×.

**Why**: filename-fallback text was "picking coffee" — the most generically
relevant English phrase across a Chinese script about coffee. Every Chinese
sentence about coffee scored highest cosine against this clip. The
anti-repetition rules in `_assign_motion_styles` only de-dupe **style
tuples**, not which footage clip is chosen.

**Proper fix**: add anti-adjacent (and ideally global frequency-cap)
constraints on `source_file` in plan.py's matching loop. A clip should not
be re-picked back-to-back, and its total usage should be soft-capped at
`ceil(total_scenes / n_clips * 1.5)`.

### 3. Final mp4 length ≠ voiceover length
**Symptom**: voiceover is 60.0s; final mp4 is 70.7s. The 10s tail has
no audio.

**Why**: scene durations come from `plan.duration_estimate_sec` (computed
from the footage clip's start/end OR `card_duration_sec` default for motion
graphics). vocut never reconciles total scene duration with voiceover
length.

**Proper fix**: in `render.py`, after concat, either (a) trim the output to
voiceover length, (b) speed-adjust scene durations proportionally, or
(c) align scenes to **sentence timing** from the voiceover (forced-aligner
like whisper-timestamps on the voiceover.wav, then each scene = its
sentence's actual spoken duration). (c) is the right answer for P1.

## 🟡 P1 — visible quality but not blocking

### 4. Section headers ignored
The script has H1 sections like `## 阿拉比卡和罗布斯塔…`. Neither vocut plan
nor the LLM picked `title_card` for these. Sections get folded into the next
sentence's matching loop and silently dropped as visual transitions.

**Fix**: when a sentence's `section` changes between consecutive items, emit
a title_card scene for the new section title (heuristic; LLM can also be told
to recognize this).

### 5. Pull quote not detected for an obvious quote
Scene 9: "精品咖啡的成本，八成花在你看不见的地方。" — clearly a quoted
saying, but LLM picked `hybrid` (picking-coffee + key_number for "八成") instead of
`pull_quote`.

**Why**: the LLM tool description biases towards literal quotation marks
(`""「」`). The script used **no quote marks** around this italicized maxim.

**Fix**: expand the pull_quote criterion in the system prompt — "maxim,
aphorism, italicized sentence, OR explicitly-marked quotation".

### 6. lottie picked the same id twice in different scenes
Scenes 2 and 11 both got `lottie_tag=data` → `lid=ripple` and
`lid=ripple` (same animation, different scenes). The seed rotation should
have avoided this, but only 1 animation in the manifest carries the `data`
tag (just ripple). Same tag + only one matching animation = repeated id.

**Fix**: expand the lottie pool. Each tag should have ≥2 animations so the
rotation actually rotates. Easiest fix: re-tag the existing 6 animations
generously (e.g. give `starfish` both "nature" AND "data" since its motion
is also data-flow-like).

## 🟢 P2 — nice-to-have

### 7. Caption sometimes covers important footage motion
On the cappuccino and dripping clips, the optional caption from `vocut
render` would overlay the most photogenic part of the footage. Currently no
captions are auto-drawn on footage scenes (we don't burn-in script text on
footage) — but this is the P1 caption feature, and once it lands, position
will matter.

### 8. CSS pseudo-shader looks "noisy" on small mobile
On 1280×720 the shader bg_style reads as moody/cinematic; if downscaled to
720×1280 (vertical reel), the conic+radial blur loses structure. The
Three.js upgrade we deferred would solve this.

### 9. Lottie animations don't match knowledge-content aesthetic
The 6 vendored animations are Airbnb test fixtures (playful characters,
festival lights, etc). For a "coffee supply chain" video, none of them
visually fit. They're working as a *technical* long-tail filler but break
visual coherence. Curate a real editorial-knowledge Lottie set as P1.

---

## What worked well

- yt-dlp via `pip install yt-dlp` → 6 clips in ~30s total over the proxy
- Whisper base model handled the Chinese voiceover for plan-side embedding
  fine (footage transcript was the issue, not voiceover)
- LLM (gpt-5.4-mini @ uyilink) correctly identified 2 of 11 scenes as
  atmospheric → picked `lottie` with sensible tags
- Style auto-assignment kept `style_diversity_score=1.0` across 7 motion
  scenes (no two scenes shared the same palette+bg+motion+fx 4-tuple)
- Filename fallback (decided + shipped in this session) was the difference
  between "0 clips indexed" and "6 clips indexed"
